| **Adjustment reasons** by hand: opening stock, correction, damage, loss, found, customer return (sign rules: damage and loss remove, opening stock, found and customer return add, correction either). Cancelling in transit returns the goods to the source and needs the cancel permission there. ## S. Step 10-a (couriers, shipments, COD settlement, real-time, returns pickup: backend) decisions

Contract: `docs/couriers-api.md`. Migration `CouriersShipmentsRealtime`. Nothing here needs provider credentials: every courier company sits behind `ICourierProvider` with a working sandbox adapter that is on by default; the six real ones are registered slots that answer `COURIER.NOT_CONFIGURED` until Step 14.

### Couriers and booking (module H)

| Decision | Reason | How to change |
| --- | --- | --- |
| **S1. The per-courier charge override is one flat customer fee, applied for the FIRST switched-on courier only.** `Courier.ChargeOverride` (null by default) replaces the base and weight fees of every domestic zone when the courier with the lowest `Priority` (then name) among the enabled ones carries it; remote surcharge and free-delivery threshold still apply. The courier is chosen after the order is placed, so a customer charge cannot depend on the courier actually booked; tying it to the first enabled courier keeps BR-004 and BR-G2 (the charge shown is the charge billed) true. | The SRS wants a per-courier override but also a charge shown before checkout. | `DeliveryService.QuoteAmountsAsync`; set or clear the field with `PUT /couriers/{id}`. A per-zone, per-courier table would need the courier chosen at checkout. |
| **S2. Courier rates (`BaseRate`, `PerExtraKgRate`, `BaseRateUpToGrams`) are what the courier charges the SHOP.** They rank the suggestion and are stored as the parcel `Cost`; they never change a customer total. Suggestion order: priority, then cost, then name. Seeded rates: sandbox 60 + 20 per extra kg; the six slots 0 (only the courier's own price list may fill them). | Margin reports (Step 11A) need the cost; the customer price stays the zone price. | `Courier.CostFor`, `CourierSelector.Rank`. |
| **S3. Booking needs a `Packed` order and does not move it.** The order becomes `HandedToCourier` only when the courier reports pickup (shipment `PickedUp`), so a cancelled booking leaves a normal packed order that can be booked again. One open forward parcel per order (a filtered unique index `UX_Shipments_OpenForward`; two simultaneous bookings: exactly one wins, the extra courier consignment is cancelled again). | Matches the order state machine (Packed to HandedToCourier) and keeps cancel-before-pickup possible. | `ShipmentBooking`, index in `CourierConfigurations`. |
| **S4. Pickup address = the fulfilling branch: `PickupAddress`, else `AddressLine`, else the branch name.** Default parcel weight is the order's weight, else 500 g. The head office has no address until the owner types one, so the name stands in rather than refusing to book. Cash to collect = `grandTotal - advancePaid` for an unpaid cash on delivery order (payment Pending), otherwise 0. | Booking must work on a fresh installation; the owner supplies the real pickup address (CLAUDE.md known issue 4). | `ShipmentBooking.PickupAddressOf`, `DefaultWeightGrams`; edit the branch. |
| **S5. Courier settings are non-secret.** `Courier.SettingsJson` takes up to 20 plain values; a key that looks like a secret (secret, password, token, api key, private, credential) is refused (`COURIER.SETTING_INVALID`). Real credentials come from configuration or the environment in Step 14, so `couriers.courier.manage-credentials` is unused and "encrypted credentials" (FR-H02) is deferred. A slot without keys cannot be switched on (`COURIER.NOT_CONFIGURED`). | Never put secrets in the database or the admin screen before an encryption and key-management decision (Step 14). | `CourierAdminService`. |
| **S6. Seeding runs only while no courier exists** (sandbox on; Pathao, Steadfast, RedX, Paperfly, eCourier, DHL off), so the owner's edits and archiving are never undone. Archived couriers are soft deleted; a courier with open parcels cannot be archived. | Same rule as the tax rule seed. | `CourierSeeder`. |

### Shipments, webhooks and polling

| Decision | Reason | How to change |
| --- | --- | --- |
| **S7. One sync path for every courier report** (webhook, polling job, sandbox simulator): idempotent by the courier's event id (`ShipmentEvent` unique on shipment and `ProviderEventId`), a repeat answers `duplicate`. Skipped scans are filled in: a report of a later status is expanded along the shortest path of the shipment state machine into inferred events (raw status `inferred`, timestamps a millisecond apart). A report that does not fit (for example "in transit" after "delivered") is recorded as a note on the timeline and changes nothing; it never throws. | Couriers skip scans and send late or repeated events; an odd report must not break an order. | `ShipmentSync`, `ShipmentStateMachine.PathTo`. |
| **S8. The order follows only through `OrderWorkflow` transitions** (history with the courier as actor, domain events, notifications, stock, cash collected). If staff already recorded a step by hand the courier's report changes nothing for the order; a step the order cannot take is a system note on the parcel (the parcel still moves). The manual `POST /orders/{id}/transition` keeps working. | Business rules win; one state machine. | `ShipmentSync.FollowOrderAsync`. |
| **S9. Webhook security reuses the payment scheme:** header `Juvo-Signature: t=<unix>,v1=<hex HMAC-SHA256 of "t.body">`, constant-time compare, 5 minute window, secret `Couriers:Sandbox:WebhookSecret` (random per process when empty). Errors carry `COURIER.*` codes. A simultaneous replay of one event applies it once (unique index); the loser may see 409 and its retry is a `duplicate`. Unknown consignments are acknowledged as `ignored` so the courier stops retrying. | FR-H07; one scheme to learn and test. A real courier's own signature scheme becomes its adapter's `ParseWebhook` in Step 14. | `WebhookSignature`, `SandboxCourierProvider.ParseWebhook`. |
| **S10. The sandbox courier is a table row (`SandboxConsignments`) with a status and a version.** Consignment ids are deterministic: `SBX-` + 8 hex digits of the order or return number + a running count (booking again gives the next count; a simultaneous booking takes the next free one). Reports carry the id `consignment:version`. Staff or tests advance it with `POST /shipments/{id}/advance`; a signed webhook can do the same; polling reads it. Bookings and cancels are saved at once (they are the courier's own side effects). The sandbox tracking link points at a reserved `.invalid` domain: there is no public sandbox page. | Needs no account, still exercises booking, events, polling and webhooks end to end. | `SandboxCourierProvider`, option `Couriers:Sandbox:TrackingUrlTemplate`. |
| **S11. Polling is the safety net:** `CourierStatusSyncWorker` (every 60 s, 200 parcels, oldest `LastPolledAt` first, `Couriers:Sync:Enabled` to switch off) asks each adapter about the open parcels and applies the answer through the same path (source `Polling`). A sweep that changed or failed is written to the job log `couriers.status-sync`. | A lost webhook only delays an update. | `Couriers:Sync:*`, `CourierWebhookService.PollOpenAsync`. |
| **S12. Failed delivery and return to sender.** `DeliveryFailed` keeps the reason (the courier's note) and counts attempts (each `OutForDelivery` is an attempt). The next step is a retry or `Returned`; `Returned` runs the existing `OrderWorkflow` rule: stock that left the shelf is restocked (`OrderRestocked` movement), stock only reserved is released. If the customer had paid, an internal note asks staff to refund (no automatic refund: money rules stay with module I). The customer gets `order.delivery-failed` and `order.returned-to-sender` messages (two new templates, English and Bengali first pass). | FR-H08, BR-002, consistent with Step 8 and the returns slice. | `ShipmentSync`, `NotificationCatalog`. |
| **S13. Cancel and re-book rules.** A parcel can be cancelled (reason required) only while `Booked`; the courier is told; the order stays `Packed`. Cancelling the ORDER while its parcel is only booked cancels the booking too, and a courier that cannot be reached is noted but never blocks the customer's cancel. Re-book = cancel (if still booked) then book again (two steps: if the new booking fails the old one stays cancelled). After pickup there is no cancel and no "intercept through the courier" call (FR-L01 second half stays open). | Matches `OrderStateMachine.CanCancel`; the customer's right to cancel before pickup does not depend on the courier. | `ShipmentBooking`, `ShipmentCancellation`. |
